## 목표와 범위

### 해결할 사용자 문제

사용자는 앱을 열지 않고도 어떤 대표 규칙이 제한을 유지하는지, 종료까지 얼마나 남았는지,
반경 밖까지 얼마나 이동해야 하는지 확인해야 한다. 위치 근거를 신뢰할 수 없거나 오래된 경우에는
이전 거리 숫자를 사실처럼 보여 주지 않아야 하며, 다른 활성 규칙이 남아 있다면 이를 함께 이해할
수 있어야 한다.

### 포함 범위

- 잠금화면 Live Activity의 `known`, `unavailable`, `stale`, 다중 규칙 상태
- Dynamic Island `minimal`, `compact`, `expanded`의 상태별 정보 우선순위와 축약 규칙
- 대표 규칙 교체, 거리 freshness, 시간 표시, 추가 제한 표시의 정보 계약
- VoiceOver 읽기 순서와 각 영역에서 축약되는 정보의 접근성 가설

### 제외 범위

- 색상·서체·간격·아이콘·motion의 최종 시각값 — `T115` 하이파이에서 확정
- Light/Dark 및 최대 Dynamic Type의 실제 배치 — `T115`에서 제작하고 `T119`에서 검증
- 코인 잔액, 구매, 해제 버튼 또는 다른 상호작용 — Live Activity 계약상 제공하지 않음
- 제품 코드와 payload 변경 — `T116` 하이파이 구현 승인 전에는 시작하지 않음

## 상태 모델

| 상태 | 발생 조건 | 사용자에게 보이는 거리 | 시간 | 추가 제한 |
|---|---|---|---|---|
| `known` | 대표 규칙의 `.inside` 위치가 신뢰 가능하고 관측 후 5분 이내 | `집 밖까지 320 m`처럼 10m 단위 숫자 | 항상 표시 | 있으면 별도 표시 |
| `unavailable` | 위치 없음, 정확도 부적합, `.inside` 미확정 등 | `거리 확인 불가` | 항상 표시 | 있으면 별도 표시 |
| `stale` | 마지막 신뢰 위치가 5분을 초과 | 이전 숫자를 제거하고 `거리 확인 불가` | 항상 표시 | 있으면 별도 표시 |
| `multiple` | 대표 규칙 외 활성 occurrence가 하나 이상 존재 | 대표 규칙의 현재 거리 상태 | 항상 표시 | `다른 제한 있음` 또는 축약 표식 |

현재 `RestrictionLiveActivityDistance`는 `known | unavailable`만 전달하므로 `stale`은 제품 UI에서
`unavailable`과 동일하게 표시한다. 로우파이의 별도 `STALE` 열은 오래된 숫자를 남기지 않는 계약을
검토하기 위한 원인 상태이며, stale 전용 제품 문구나 payload 필드를 새로 요구하지 않는다.

## 정보 구조

### 잠금화면

1. 대표 규칙 이름
2. 종료까지 남은 시간
3. 남은 거리 또는 `거리 확인 불가`
4. 다른 활성 규칙 존재 여부

대표 규칙과 카운트다운을 첫 행에 두고 거리와 다른 제한 표시는 둘째 행에 둔다. 다중 규칙 상태에서도
각 규칙의 상세 목록을 펼치지 않고 대표 규칙 하나만 유지한다. 카드 좌우 padding은 각각 16pt로
맞추며, 카운트다운의 trailing 여백도 16pt로 정렬한다. 거리는 선이 많은 조준선 형태가 아니라
단순한 채움형 SF Symbol `location.fill`로 표시한다. 대표 규칙 이름은 의미가 명확한 전용 아이콘이
없으므로 임시 기호를 붙이지 않고 텍스트만 표시한다.

`10m 단위 반올림 · 좌표/주소 미표시`, `시간은 계속 표시 · 해제 행동 없음`,
`이전 80m 숫자를 즉시 제거 · UI는 unavailable과 동일`은 사용자 문구가 아니다. 이 정보는 실제
Live Activity 카드 안에서 제거하고 Figma 보드의 상태 설명과 이 문서에서만 구현 계약으로 유지한다.

### Dynamic Island expanded

1. leading: 대표 규칙 이름
2. trailing: 종료까지 남은 시간
3. bottom: 남은 거리 또는 `거리 확인 불가`
4. bottom trailing: `다른 제한 있음`

### Dynamic Island compact

- leading: `320 m` 또는 `?`로 축약한 거리 상태
- trailing: 한국어는 `42분`, 영어는 `42 min`처럼 거리 단위 `m`와 구분되는 축약 카운트다운
- 다중 규칙: 공간이 허용되는 경우 `+` 표식을 추가하고 VoiceOver에서는 `다른 제한 있음`으로 제공

### Dynamic Island minimal

- 종료까지 남은 시간만 최우선으로 유지하되 한국어 `분`, 영어 `min` 단위를 명시한다.
- 거리 availability와 다중 규칙 표시는 expanded 또는 compact에서 확인한다.
- minimal 하나만 보이는 상황에서도 제한 종료 시점을 놓치지 않는 것을 우선한다.

## 상호작용과 검증 규칙

- Live Activity는 읽기 전용이다. 버튼, 토글, 코인 잔액, 구매 진입을 추가하지 않는다.
- 카운트다운은 `endsAt` 기반 동적 날짜 텍스트를 사용하며 0 아래로 내려가지 않는다.
- `known` 거리만 숫자로 표시하며 `max(0, radius - centerDistance)`를 가장 가까운 10m로 반올림한다.
- 위치 근거가 5분을 초과하면 이전 거리 숫자를 유지하지 않고 `거리 확인 불가`로 바꾼다.
- 대표 occurrence가 끝나고 다른 occurrence가 남으면 같은 Live Activity를 다음 대표 규칙으로 갱신한다.
- 모든 활성 occurrence가 끝나면 Live Activity를 종료한다.
- 좌표, 주소, 위치 정확도, 앱 token을 표시하거나 payload에 넣지 않는다.
- attributes와 content state의 합계를 4KB 미만으로 유지한다.

## 접근성 가설

- 잠금화면 읽기 순서: 대표 규칙 → 남은 시간 → 남은 거리 또는 확인 불가 → 다른 제한 있음
- expanded 읽기 순서는 잠금화면과 동일하게 유지한다.
- compact는 거리 상태와 남은 시간을 각각 의미 있는 label/value로 제공한다. 시각적 `?`는
  VoiceOver에서 `거리 확인 불가`로 읽는다.
- minimal은 남은 시간을 하나의 요소로 읽으며 장식 아이콘을 별도 요소로 노출하지 않는다.
- 시간의 `분/min`과 거리의 `m`를 구분해 단위만 보아도 의미가 섞이지 않게 한다.
- 다중 규칙의 `+` 표식은 기호 이름이 아니라 `다른 제한 있음`으로 읽는다.
- 레이아웃 컨테이너, spacing, padding, 장식 아이콘은 VoiceOver 요소로 만들지 않는다.
- 시간과 거리는 색상만으로 구분하지 않고 위치, 문구, 단위를 함께 사용한다.

## 검토할 선택점

1. minimal에서 거리나 다중 규칙 표식보다 남은 시간 하나를 우선하는 구조가 적절한가?
2. compact의 거리 확인 불가를 시각적으로 `?`로 축약하되 VoiceOver에서는 전체 문구로 읽는 방식이
   적절한가?
3. stale을 별도 사용자 문구로 구분하지 않고 `거리 확인 불가`로 수렴시키는 방식이 적절한가?
4. 다중 규칙은 잠금화면·expanded에서 `다른 제한 있음`, compact에서 `+`, minimal에서는 생략하는
   단계적 축약이 적절한가?

- [x] 오래된 거리 숫자를 유지하지 않는 5분 stale 계약을 반영했다.

- [x] Live Activity에 코인·구매·해제 행동을 넣지 않았다.
