## 목표와 범위

### 해결할 사용자 문제

Shield에서 `해제권 1회 사용`을 확정한 사용자가 GetUp으로 이동한 뒤 요청이 사라졌거나 다시
차감될까 불안하지 않도록, 현재 처리 상태와 확정 결과를 한 흐름에서 이해하게 한다. 앱이 처리 도중
종료돼도 같은 command를 복원하고, 제한 read-back과 장부 commit이 확인된 뒤에만 성공을 알리는 것이
성공 조건이다.

### 포함 범위

- Shield에서 만든 `releaseProcessing` route의 메인 앱 진입과 즉시 처리 중 상태
- 신규 승인 대상인 `processing`, `completed`, `retryable`, `insufficient` 네 화면
- 처리 도중 앱 종료 후 같은 command 재조정과 terminal 화면 복원
- 재시도 대기 시간, 중복 행동 차단과 같은 command ID 재시도
- 완료 시 사용한 수단과 다른 규칙으로 남는 제한 안내
- 잔액 부족 시 기존 코인 구매 화면으로 이동
- `recoveryRequired`에서 기존 iCloud 장부 복구 화면으로 연결

### 제외 범위

- Shield 자체의 대상·비용 확인 UI 변경
- 코인 상점과 기존 iCloud 장부 복구 화면의 재설계
- Live Activity 잠금화면·Dynamic Island 개편 — `T114~T119`에서 별도 진행
- 색상·서체·간격·아이콘·motion의 최종 규격과 SwiftUI 구현
- CloudKit 원본 오류, command ID, occurrence ID와 내부 동기화 단계의 사용자 노출

## 핵심 정보 구조

모든 신규 화면은 다음 순서를 유지한다.

1. 현재 상태: 처리 중·완료·다시 시도 필요·해제권 부족
2. 대상: 대표 규칙과 이번 적용 구간 종료 시각
3. 결과: 차감 여부, 사용한 수단, 현재 제한 유지 여부
4. 다른 규칙 영향: 해제 뒤 남거나 이미 남아 있는 제한
5. 한 개의 주 행동과 필요한 경우 한 개의 보조 행동

처리 중 화면은 결과를 추측하지 않는다. 완료 화면만 사용한 수단과 확정 잔액을 표시하며,
재시도·부족 화면은 코인이 차감되지 않았고 제한이 유지되고 있음을 먼저 알린다.

## 사용자 흐름

1. 사용자가 Shield에서 대상·종료 시각·무료 우선/구매 1개 fallback·남을 제한을 확인하고
   `해제권 1회 사용`을 누른다.
2. Shield는 `releaseProcessing` route를 저장한다. iOS 26.5 이상은 GetUp을 즉시 열고, iOS
   26.0~26.4는 사용자가 직접 GetUp을 열도록 fail-closed 안내한다.
3. 앱은 활성 occurrence와 `pending` route를 검증해 `processing`으로 원자 claim한 직후
   `US2-RH-LF-01`을 표시한다. 닫기·재시도·뒤로가기는 제공하지 않는다.
4. 앱은 기존 미종결 command 재조정, 전체 장부 동기화, occurrence 재검증, 무료 우선 예약, 예외
   적용, 제한 read-back과 장부 commit을 수행한다.
5. read-back과 commit이 모두 확인되면 `US2-RH-LF-02`로 전환한다. 사용자가 `확인`을 누르면
   terminal handoff를 확인 처리하고 삭제한 뒤 현재 제한 화면 또는 홈으로 돌아간다.
6. 재시도 가능한 오류이거나 앱 재실행 뒤 완료되지 않은 중단 command로 확정되면
   `US2-RH-LF-03`을 표시한다. `retryAfter` 전에는 재시도 버튼을 비활성화하고, 이후에는 같은
   command ID로만 재시작한다. `닫기`는 현재 terminal handoff를 확인 처리하고 삭제한다.
7. 최신 장부에서 무료·구매 잔액이 모두 0으로 확정되면 `US2-RH-LF-04`를 표시한다.
   `코인 구매`는 handoff를 확인 처리한 뒤 기존 코인 상점으로 이동하고, `닫기`는 제한을 유지한 채
   이전 화면으로 돌아간다.
8. 계정·장부 복구가 필요하면 신규 결과 화면을 만들지 않고 `US2-RH-LF-05` 연결 상태를 거쳐 기존
   iCloud 복구 화면을 연다. 이동 또는 닫기를 사용자가 명시적으로 선택할 때 terminal handoff를
   확인 처리한다.
9. 처리 중 앱이 종료되면 다음 foreground에서 `processing` handoff를 새 요청보다 먼저 재조정하고,
   새 차감 없이 `completed | retryable | insufficient | recoveryRequired` 중 하나로 수렴한다.

## 상호작용과 검증 규칙

- `processing` 진입 즉시 화면을 표시하며 동기화 완료를 기다린 뒤 화면을 여는 구조로 만들지 않는다.
- `processing`에서는 닫기, swipe dismiss, 뒤로가기, 재시도와 추가 해제 요청을 모두 차단한다.
- 진행 표시는 무한 spinner만 두지 않고 제목과 현재 제한 유지 설명을 함께 제공한다. 내부 단계나
  네트워크 횟수는 노출하지 않는다.
- 결과 불명·충돌·부분 실패는 재조정하는 동안 계속 `processing`이다. 단순 timeout만으로
  `retryable`을 표시하지 않는다.
- `completed`는 Managed Settings read-back과 장부 commit을 모두 확인한 뒤에만 표시한다.
- `completed`는 실제 funding source를 `무료 해제권 1회` 또는 `구매 코인 1개`로 표시한다. Shield의
  local mirror에서 예상한 수단을 재사용하지 않는다.
- 다른 활성 규칙이 같은 앱을 계속 제한하면 이를 성공 결과의 일부로 표시하며 해제 실패처럼
  표현하지 않는다.
- `retryable`은 제한 유지와 미차감·보상 완료를 명시한다. 같은 command ID로만 재시도하고 새 요청을
  만들지 않는다.
- `retryAfter`가 있으면 남은 시간을 숫자로 안내하고 버튼을 비활성화한다. 시각만 달라져도 자동으로
  버튼 상태를 갱신하며 화면을 다시 열도록 요구하지 않는다.
- `닫기`는 재시도를 취소한다는 명시적 terminal action이다. 제한과 잔액은 바꾸지 않고 handoff를
  확인 처리한 뒤 삭제한다.
- `insufficient`는 최신 장부가 `current`이고 무료·구매 잔액이 모두 0인 경우에만 표시한다. stale,
  sign-out, 삭제나 복구 필요 상태를 부족으로 바꾸지 않는다.
- `코인 구매`를 누르면 terminal handoff를 확인 처리한 뒤 기존 `CoinStoreView`로 이동한다. 구매가
  성공해도 이전 command를 자동 재실행하지 않으며 사용자가 새 해제를 명시적으로 요청한다.
- `recoveryRequired`는 기존 iCloud 복구 화면을 재사용하고 코인 구매 CTA를 표시하지 않는다.
- 단순 terminal 화면 제시는 handoff를 삭제하지 않는다. 사용자의 `확인`, `닫기`, `코인 구매`,
  복구 행동 또는 재시도만 영속 상태를 변경한다.
- 앱 재실행은 `processing | terminal` 상태를 복원하며, 이미 완료된 command를 다시 차감하지 않는다.
- 제품 문구에는 CloudKit, CKError, command ID, record, token, 좌표와 계정 식별자를 노출하지 않는다.

## 접근성 가설

- VoiceOver 읽기 순서: 상태 제목 → 상태 설명 → 대상 규칙·구간 → 차감 또는 미차감 결과 → 남은 제한
  → 주 행동 → 보조 행동 순으로 유지한다.
- `processing` 제목은 첫 표시와 재실행 재조정에서 한 번 live announcement하고 spinner 자체는
  접근성에서 숨긴다. 반복 announcement로 읽기를 방해하지 않는다.
- terminal 전환 시 focus를 새 화면의 상태 제목으로 이동한다. 코인 상점·복구 화면 이동 뒤에는 해당
  화면의 상태 heading으로 이동한다.
- `retryAfter`가 끝나 버튼이 활성화되면 `다시 시도할 수 있어요`를 한 번 알리되 자동 실행하지 않는다.
- Dynamic Type 최대 크기에서는 상태 카드와 action을 세로로 쌓고 전체 화면을 scroll한다. action은
  화면 하단 고정으로 본문을 가리지 않는다.
- 색상 외에도 상태별 아이콘, 제목, 결과 문구를 사용한다. 성공·경고·오류를 색상만으로 구분하지
  않는다.
- 모든 action은 최소 `44×44pt` touch target을 유지한다. 비활성 재시도는 비활성 이유와 남은 대기를
  accessibility value로 제공한다.
- Reduce Motion에서는 spinner를 정적인 진행 아이콘으로 대체할 수 있고, 상태 전환은 cross-fade나
  즉시 교체로 전달한다. 의미를 이동·scale animation에 의존하지 않는다.
- 한국어·영어 모두 규칙명과 시각이 길어져도 잘리지 않게 줄바꿈하며, 무료 `회`와 구매 `개` 단위를
  구분해 읽는다.

## 검토할 선택점

1. 완료 뒤 다른 규칙 제한이 남을 때 기본 CTA를 `확인`으로 유지하고 현재 제한 화면으로 돌아가는
   흐름이 적절한가?
2. 재시도 화면에서 `닫기`가 현재 요청을 끝내되 제한을 유지한다는 의미가 충분히 분명한가?
3. 잔액 부족 뒤 코인 구매가 완료돼도 자동 재시도하지 않고 사용자가 새 해제를 요청하게 하는 흐름이
   적절한가?
4. 처리 중 화면에서 앱 종료 가능성 설명을 항상 노출할지, 재실행으로 복원된 경우에만 노출할지
   결정이 필요한가?
