# 기능 명세: 제한 현황 Live Activity와 일회성 해제 코인

**기능 브랜치**: `codex/live-activity-coins-clarifications`

**작성일**: 2026-09-01

**상태**: 명세·계획·작업 생성 및 분석 보완 완료

**입력**: 사용자 설명: "Live Activity로 제한 시작을 알리고 해제까지 남은 거리와 시간을 표시한다. 규칙을 한 번 해제할 수 있는 코인 제도와 인앱결제 시스템을 도입한다."

## Clarifications

### Session 2026-09-01

- Q: iCloud 장부를 확인할 수 없는 상태에서 사용자가 코인 구매를 시도하면 어떻게 처리할까요? → A: 구매 버튼을 비활성화하고 iCloud 연결 후 다시 시도하도록 안내한다.
- Q: 사용자가 진행 중인 Live Activity를 직접 지운 뒤 같은 제한 구간에서 앱을 다시 열면 Live Activity를 다시 만들까요? → A: 제한이 활성 상태라면 앱을 foreground로 열 때마다 다시 생성한다.
- Q: 초기 출시에서 판매할 코인 묶음 수량을 어떻게 구성할까요? → A: 1개, 3개, 5개 묶음을 판매한다.
- Q: 사용자가 CloudKit 개인 장부를 삭제해 기존 구매·사용 내역을 안전하게 복원할 수 없을 때 코인 기능을 어떻게 처리할까요? → A: 코인 기능을 잠그고 불이익을 사전 고지하며, 사용자 확인 후 구매 코인 0개·현재 월 무료 해제권 0회로 새 장부를 시작한다.
- Q: 코인으로 한 규칙을 해제했지만 다른 활성 규칙이 남아 있다면 Live Activity를 어떻게 처리할까요? → A: 다른 규칙이 남으면 기존 Live Activity를 다음 대표 규칙으로 갱신하고, 모든 활성 규칙이 해제됐을 때만 종료한다.
- Q: Shield에서 코인 해제에 성공했지만 GetUp 앱이 실행되지 않은 경우 Live Activity 갱신 시점을 어떻게 보장할까요? → A: Shield Action의 직접 갱신·종료를 실기기에서 먼저 검증해 성공하면 즉시 반영하고, 지원되지 않거나 실패·timeout이면 해제와 차감은 유지한 채 앱 직접 진입 또는 다음 foreground에서 재조정한다.
- Q: 무료 해제권 우선 사용에 필요한 월간 지급 로직을 어느 단계에서 구현할까요? → A: 월 계산·무료분 생성·원자적 예약 로직을 공통 기반으로 먼저 구현하고, 월간 잔액 UI·지역화·월 경계 인수 검증은 월간 무료 해제권 사용자 스토리에서 구현한다.
- Q: 사용자의 90%가 30초 안에 해제 정보를 이해하고 코인 사용을 완료한다는 성공 기준을 어떻게 검증할까요? → A: 구현 완료 기준은 자동 검증 가능한 사전 정보 표시와 명시적 확인 동작으로 변경하고, 90% 이해율은 별도의 사용성 검증 목표로 관리한다.
- Q: Shield가 앱 이동 목적을 기록한 뒤 사용자가 GetUp을 늦게 열면 해당 이동 요청을 언제까지 유효하게 사용할까요? → A: 생성 후 5분 이내이고 연결된 제한 구간이 여전히 활성일 때 한 번만 소비하며, 만료·중복·종료된 구간의 요청은 삭제한다.
- Q: Live Activity 시작 성공률 95%를 측정할 때 어떤 실행 사례를 포함할까요? → A: Live Activity 지원 기기, 권한 허용, 유효한 활성 제한, 앱 foreground 조건을 모두 만족하는 100회 실행을 모집단으로 삼고 95회 이상 30초 이내 표시되는지 검증한다. 권한 거부·미지원 상태는 별도 안전 실패 테스트로 다룬다.
- Q: 위치가 갱신된 뒤 30초 이내 Live Activity 거리 갱신 기준은 어느 시점부터 적용할까요? → A: 메인 앱이 신뢰 가능한 위치를 전달받아 ActivityKit을 조정할 수 있는 시점부터 30초를 측정한다. extension만 받은 위치는 저장하고 다음 앱 foreground에서 반영한다.
- Q: 앱 재설치나 새 기기에서 구매 코인 잔액을 복구할 때 어떤 조건을 충족해야 복구 성공으로 볼까요? → A: 로컬 데이터가 없는 새 설치에서 동일 iCloud 계정의 기존 CloudKit 장부가 current이면 검증된 미사용 구매 코인 잔액과 관련 내역을 복구한다. 기존 장부가 없으면 자동 복구하지 않으며, 초기 fetch 뒤 삭제 증거도 없는 최초 활성화는 `setupRequired`, 삭제 확인은 `deletionConfirmed`, 불확실 상태는 재시도로 분리한다.
- Q: Shield에서 해제권 버튼을 누른 뒤 CloudKit 응답을 얼마나 기다릴까요? → A: 최대 5초 동안 기다리고, 그 안에 성공을 확인하지 못하면 제한을 유지한 채 앱의 상태 확인 화면으로 유도한다. 결과가 불명확한 장부 명령은 재조정해 사용할 수 없는 차감이 남지 않게 한다.
- Q: 매월 무료 해제권 2회는 언제 장부에 생성할까요? → A: 새달의 첫 앱 실행 또는 Shield 해제 요청에서 생성한다. Shield 요청이면 해당 월 생성과 1회 사용 예약을 하나의 원자적 장부 명령으로 처리한다.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 제한 상태와 남은 해제 조건 확인 (Priority: P1)

사용자는 앱이 foreground에서 활성 제한을 확인해 Live Activity를 시작한 이후에는 앱을 다시 열지
않고도 해당 규칙, 종료까지 남은 시간, 반경 밖까지 남은 최소 이동 거리를 확인한다.

**이 우선순위인 이유**: 제한이 왜 유지되고 언제·어떻게 해제되는지 즉시 알 수 있어야 자동 제한을 신뢰할 수 있다.

**독립 테스트**: 코인·결제 없이 한 규칙의 제한을 시작하고 Live Activity의 시작, 시간·거리 갱신, 자동 종료를 확인한다.

**인수 시나리오**:

1. **Given** 규칙의 시간·위치 조건이 모두 충족됐을 때, **When** 앱이 foreground에서 활성 제한을 확인하면, **Then** 제한 시작과 규칙 정보를 Live Activity에서 확인한다.
2. **Given** 사용자가 기준 장소 반경 안에 있을 때, **When** 메인 앱이 신뢰할 수 있는 위치를 전달받아 ActivityKit을 조정할 수 있으면, **Then** 반경 밖까지의 남은 최소 거리가 갱신된다. extension만 위치를 전달받으면 근거를 저장하고 다음 앱 foreground에서 반영한다.
3. **Given** 정확한 위치를 확인할 수 없을 때, **When** Live Activity를 표시하면, **Then** 남은 시간은 표시하되 거리는 확인 불가로 표시한다.
4. **Given** 한 규칙의 시간 또는 위치 조건이 종료됐을 때, **When** 활성 규칙 집합을 다시 계산하면, **Then** 다른 활성 규칙이 남으면 기존 Live Activity를 다음 대표 규칙으로 갱신하고 모두 종료됐으면 Live Activity를 종료한다.
5. **Given** 사용자가 Live Activity를 직접 지웠지만 제한은 계속 활성일 때, **When** 앱을 다시 foreground로 열면, **Then** 현재 대표 규칙의 Live Activity를 다시 생성한다.

### 사용자 스토리 2 - 코인으로 현재 규칙 1회 해제 (Priority: P1)

사용자는 예외적으로 앱을 사용해야 할 때 무료 해제권 1회 또는 구매 코인 1개를 사용해 선택한 활성 규칙의 현재 적용 구간을 해제한다.

**이 우선순위인 이유**: 코인의 핵심 가치이며 잘못된 대상 해제나 중복 차감은 유료 재화와 제한 신뢰를 훼손한다.

**독립 테스트**: 무료 해제권 또는 테스트 구매 코인으로 활성 규칙을 해제하고, 해당 규칙의 이번 구간만 해제되며 사용한 잔액만 1 감소하는지 확인한다.

**인수 시나리오**:

1. **Given** 무료 해제권 또는 구매 코인이 있고 규칙이 활성일 때, **When** 해제 대상·소모·유효 기간을 확인하고 사용을 확정하면, **Then** 우선순위에 따른 해제 수단 1회가 차감되고 해당 규칙의 현재 구간만 해제된다.
2. **Given** 두 규칙이 같은 앱을 제한할 때, **When** 한 규칙에 코인을 사용하면, **Then** 다른 규칙이 요구하는 제한은 유지되며 이를 확정 전에 안내한다.
3. **Given** 무료 해제권과 구매 코인 잔액이 모두 0일 때, **When** Shield의 해제권 사용 버튼을 누르면, **Then** 규칙은 유지하고 잔액 부족을 안내한 뒤 앱의 코인 구매 화면으로 진입하도록 유도한다.
4. **Given** 같은 규칙 구간에 중복 해제를 요청했을 때, **When** 첫 해제가 완료되면, **Then** 코인은 최대 1개만 차감된다.
5. **Given** 해제가 완료되지 않았을 때, **When** 처리가 실패하면, **Then** 코인을 차감하지 않거나 자동으로 원상 복구한다.
6. **Given** Shield의 해제권 요청 후 5초 안에 최신 장부의 성공 응답을 확인하지 못했을 때, **When** 요청 대기가 끝나면, **Then** 제한을 유지하고 앱의 상태 확인 화면으로 유도하며 결과가 불명확한 차감은 재조정한다.

### 사용자 스토리 3 - 코인 구매와 잔액 확인 (Priority: P2)

사용자는 코인 묶음의 수량과 현지 가격을 확인하고 인앱에서 구매하며, 구매가 확정된 후 정확한 잔액을 확인한다.

**이 우선순위인 이유**: 수익 경로이며 결제 완료와 잔액 일치가 유료 재화의 필수 신뢰 조건이다.

**독립 테스트**: 구매 1건을 성공·취소·대기·실패로 각각 처리하고 성공한 건만 한 번 잔액에 반영되는지 확인한다.

**인수 시나리오**:

1. **Given** 코인 상품이 판매 가능할 때, **When** 구매 화면을 열면, **Then** 1개·3개·5개 묶음과 각 상품의 현지 통화 가격을 확인한다.
2. **Given** 구매가 확정됐을 때, **When** 결과가 반영되면, **Then** 구매한 수량이 잔액에 한 번만 추가된다.
3. **Given** 구매가 취소·실패됐을 때, **When** 흐름이 종료되면, **Then** 잔액은 변하지 않는다.
4. **Given** 구매가 승인 대기 중일 때, **When** 구매 화면을 다시 열면, **Then** 대기 상태를 표시하고 승인 전에 코인을 지급하지 않는다.
5. **Given** 같은 구매 결과가 다시 전달됐을 때, **When** 잔액을 갱신하면, **Then** 중복 지급하지 않는다.
6. **Given** iCloud 계정 또는 최신 장부 상태를 확인할 수 없을 때, **When** 구매 화면을 열면, **Then** 구매 버튼을 비활성화하고 iCloud 연결 후 다시 시도하도록 안내한다.
7. **Given** 사용자가 코인 기능을 처음 활성화하거나 구매를 확정하기 전, **When** 데이터 복구 조건을 확인하면, **Then** iCloud 장부 삭제 시 기존 구매 잔액과 현재 월 무료분을 복원하지 못할 수 있음을 확인한다.
8. **Given** 로컬 코인 데이터가 없는 재설치·새 기기에서 이전과 동일한 iCloud 계정을 사용하고 기존 CloudKit 장부가 current일 때, **When** 코인 상태를 동기화하면, **Then** 검증된 구매 지급에서 사용·보정 내역을 반영한 미사용 구매 코인 잔액과 관련 내역을 복구한다.
9. **Given** 초기 fetch가 끝났지만 원격 장부와 삭제 증거가 모두 없는 최초 사용자일 때, **When** 데이터 한계 고지에 동의하고 최초 활성화 action을 확정하면, **Then** `CoinLedgerSetupService`가 initial ledger와 해당 월 무료 해제권 2회를 한 번의 원자적 명령으로 만들고 UI를 `current` 잔액 상태로 갱신한다.
10. **Given** `userDeletedZone` 또는 기존 장부 보유 증거 뒤 zone 부재로 삭제가 확인됐을 때, **When** 사용자가 새 장부 시작을 확정하면, **Then** 구매 코인 0개·삭제 월 무료 해제권 0회로 시작하고 다음 서울 기준 월부터 무료 2회를 다시 제공한다.

### 사용자 스토리 4 - 매월 무료 해제권 사용 (Priority: P2)

사용자는 매월 두 번의 예외 상황에서 결제 없이 현재 규칙을 해제할 수 있고, 이번 달 남은 무료 해제 횟수와 구매 코인을 구분해 확인한다.

**이 우선순위인 이유**: 실수나 긴급 상황을 위한 기본 안전장치를 제공하면서도 무료분의 무제한 누적으로 제한 기능의 목적이 약해지는 것을 막는다.

**독립 테스트**: 월 변경, 신규 사용자, 여러 기기 동시 접속을 각각 재현해 해당 월의 무료 해제권이 최대 2회만 제공되고 남은 무료분이 다음 달로 이월되지 않는지 확인한다.

**인수 시나리오**:

1. **Given** 기존 사용자가 새 달에 처음 앱을 열거나 Shield의 해제권 사용 버튼을 누를 때, **When** 최신 장부에서 월간 지급 상태를 확인하면, **Then** 이번 달 무료 해제권을 최대 2회로 생성하고 Shield 요청이면 그중 1회를 같은 해제 명령에서 우선 사용한다.
2. **Given** 이번 달 무료 해제권이 남아 있을 때, **When** 규칙 해제를 확정하면, **Then** 무료 해제권을 먼저 1회 차감하고 구매 코인은 유지한다.
3. **Given** 무료 해제권을 일부 또는 전부 남긴 채 다음 달이 됐을 때, **When** 새 달의 지급 상태를 확인하면, **Then** 이전 달 무료분은 이월하지 않고 이번 달 무료 해제권을 2회로 갱신한다.
4. **Given** 사용자가 월 중간에 처음 사용을 시작했을 때, **When** 무료 지급 자격을 확인하면, **Then** 해당 월의 무료 해제권 2회를 한 번 지급한다.
5. **Given** 같은 iCloud 계정의 여러 기기가 같은 달의 지급을 요청했을 때, **When** 지급 결과가 동기화되면, **Then** 계정 전체에 해당 월의 무료 해제권을 최대 2회만 제공한다.

### 경계 사례

- 두 개 이상의 규칙이 동시에 활성화될 때는 확정된 다중 규칙 표시 정책을 따른다.
- 위치 오차가 반경 경계와 겹치면 남은 거리를 확정값으로 표시하지 않고 제한 상태도 임의로 변경하지 않는다.
- Live Activity가 꺼져 있거나 표시 실패해도 제한 판정·해제는 계속 동작한다.
- Live Activity 권한 거부·미지원 상태는 시작 성공률 모집단에서 제외하되, 제한 판정·적용·해제가
  영향을 받지 않는 안전 실패 경로로 별도 검증한다.
- 앱이 실행되지 않은 상태에서 제한이 시작되면 Shield는 정상 적용하되 Live Activity는 자동 시작하지 않고, 앱이 다음에 foreground에서 활성 제한을 확인할 때 시작한다.
- 사용자가 Live Activity를 직접 지워도 활성 제한 자체는 유지되며, 같은 제한 구간에서 앱을 다시 foreground로 열면 Live Activity를 다시 생성한다.
- 코인 확정 중 앱 종료·기기 잠금이 발생하면 해제와 차감을 하나의 결과로 재확인한다.
- Shield의 해제권 요청은 CloudKit 성공 응답을 최대 5초 기다린다. 시간 안에 성공을 확인하지 못하면 제한을 유지하고 앱의 상태 확인 화면으로 유도하며, 늦게 완료되었거나 결과가 불명확한 장부 명령은 요청 식별자로 재조정해 사용할 수 없는 차감이 남지 않게 한다.
- 코인 사용 직전에 규칙이 자동 종료되면 코인을 차감하지 않는다.
- 해제한 규칙 구간 중 앱 재실행·기기 재부팅이 발생해도 같은 구간에 제한을 다시 적용하지 않는다.
- 구매가 나중에 승인되면 승인 시점에 한 번만 지급한다.
- 구매가 환불·철회되면 미사용 코인 범위에서 잔액을 보정하되 음수 잔액을 만들지 않는다.
- 가격 로드·네트워크·결제 실패 시 잘못된 가격을 표시하지 않고 기존 잔액을 보존한다.
- 월이 바뀌는 순간 앱이나 Shield가 실행 중이지 않으면 다음 실행 시 새 달의 무료 해제권을 반영한다.
- 기기 날짜가 변경되거나 여러 기기에서 동시에 실행돼도 같은 계정·같은 달에 무료 해제권을 중복 지급하지 않는다.
- iCloud 계정 상태를 확인할 수 없으면 월간 무료 지급을 확정하지 않고 상태가 확인된 뒤 안전하게 재시도한다.
- iCloud 동기화가 최신 상태가 아니면 StoreKit 구매를 시작하지 않고 기존 잔액과 미완료 거래를 보존한다.
- 일시적인 iCloud 오류와 달리 CloudKit 개인 장부 삭제가 확인되면 코인 구매·사용을 잠그고 자동으로 로컬 잔액을 복원하거나 0으로 초기화하지 않는다.
- CloudKit 장부 삭제 후 사용자가 새 장부 시작을 명시적으로 확정하면 구매 코인 0개·현재 월 무료 해제권 0회로 시작하고, 다음 `Asia/Seoul` 월 경계부터 무료 해제권 2회를 지급한다.
- 재설치·새 기기에서 로컬 코인 데이터가 비어 있어도 동일 iCloud 계정의 기존 CloudKit 장부가 current이면 해당 장부를 기준으로 검증된 미사용 구매 코인 잔액과 관련 내역을 복구한다. 원격 장부·삭제 증거가 모두 없는 최초 활성화는 고지 뒤 initial ledger를 만들고, 삭제 확인은 잠금·reset 안내, current 미확인은 잠금·재시도 안내를 적용하며 어떤 경우에도 로컬 mirror나 StoreKit 거래만으로 잔액을 재구성하지 않는다.
- Shield의 해제권 사용 버튼은 무료분 우선·무료분이 없으면 구매 코인 1개 사용에 대한 명시적 확정이다. 최신 장부의 수단이 화면의 local mirror와 달라도 이 우선순위 안에서만 처리한다.
- 최신 장부가 정상이지만 잔액만 부족하면 앱의 코인 구매 화면으로 유도한다. iCloud·장부가 불가하거나 삭제·재조정 상태이면 결제를 시작하지 않고 앱의 해당 복구 안내로 유도한다.
- iOS 26.5 이상에서는 Shield Action의 공식 앱 열기 응답을 사용하고, iOS 26.0~26.4에서는 지원되지 않는 우회 API를 사용하지 않은 채 안내 후 현재 차단 앱을 닫아 사용자가 GetUp을 직접 열게 한다.
- Shield Action에서 메인 앱이 시작한 Live Activity의 직접 갱신·종료가 실기기에서 확인되면 해제 성공 직후 이를 우선 수행한다. ActivityKit 접근이 지원되지 않거나 실패·timeout이어도 성공한 제한 해제와 장부 차감을 되돌리지 않고, iOS 26.5 이상은 앱 직접 진입, iOS 26.0~26.4는 다음 앱 foreground에서 재조정한다.
- Shield가 기록한 앱 이동 요청은 생성 후 5분 이내이고 연결된 제한 구간이 여전히 활성일 때 한 번만
  소비한다. 만료됐거나 이미 소비했거나 연결된 제한 구간이 종료된 요청은 삭제하고 자동 이동하지
  않는다. iCloud·장부 문제가 계속되면 이동 요청 만료와 무관하게 앱이 현재 상태를 다시 평가해
  복구 안내를 표시한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 앱이 foreground에서 제한 시작 또는 현재 활성 제한을 확인하면 Live Activity를 시작해야 한다. 앱 비실행 상태의 자동 제한 시작에는 Live Activity 시작을 보장하지 않아야 한다.
- **FR-002**: Live Activity는 규칙 식별 정보, 현재 제한 상태, 종료까지 남은 시간, 반경 밖까지 남은 최소 거리를 표시해야 한다.
- **FR-003**: 남은 거리는 `max(0, 설정 반경 - 기준점까지의 현재 직선거리)`로 계산한 뒤 가장 가까운 10m 단위로 반올림하고 항상 미터 단위로 표시해야 한다. 정확히 중간인 5m는 큰 쪽 10m로 반올림해야 한다.
- **FR-004**: 두 개 이상의 규칙이 동시에 활성화될 때 Live Activity는 가장 먼저 활성화된 대표 규칙 하나만 표시하고 다른 활성 규칙이 있음을 함께 알려야 한다. 대표 규칙이 종료되면 남은 규칙 중 가장 먼저 활성화된 규칙으로 교체해야 한다.
- **FR-005**: 기존 `LocationEvidenceEvaluator`가 위치를 `.inside`로 확정하지 못하거나 마지막 신뢰 위치가 5분을 초과하면 지난 거리를 현재값처럼 표시하지 않고 거리 확인 불가를 안내해야 한다.
- **FR-006**: 종료까지 남은 시간은 0 미만으로 표시하지 않아야 한다.
- **FR-007**: 규칙이 자동 종료되거나 코인으로 해제되면 활성 규칙 집합을 다시 계산해야 한다. 다른 활성 규칙이 남으면 기존 Live Activity를 다음 대표 규칙으로 갱신하고, 활성 규칙이 하나도 없을 때만 Live Activity를 종료해야 한다. Shield Action의 직접 ActivityKit 조정이 실기기에서 확인되면 이를 우선 사용하고, 지원되지 않거나 실패·timeout이면 성공한 제한 해제와 장부 차감을 유지한 채 앱 직접 진입 또는 다음 foreground에서 재조정해야 한다.
- **FR-008**: Live Activity를 사용할 수 없어도 제한 판정·적용·해제는 독립적으로 동작해야 한다.
- **FR-009**: 사용자는 현재 무료 해제권과 구매 코인 잔액을 구분해 확인할 수 있어야 한다.
- **FR-010**: 무료 해제권 1회 또는 구매 코인 1개는 선택한 활성 규칙 1개의 현재 적용 구간만 해제하고 다음 반복 구간에는 적용되지 않아야 한다.
- **FR-011**: 코인 사용 전에 대상 규칙, 소모 수량, 해제 유효 기간, 겹친 규칙으로 남을 제한을 안내하고 명시적 확인을 받아야 한다.
- **FR-012**: Shield의 해제권 사용 버튼을 누른 뒤 최신 장부에서 선택한 규칙의 현재 구간이 여전히 활성이고 무료 해제권 또는 구매 코인 잔액이 1 이상임을 5초 안에 확인한 경우에만 해제해야 한다. 버튼은 무료분 우선, 무료분이 없으면 구매 코인 1개 사용에 대한 명시적 확정이어야 한다. 5초 안에 성공을 확인하지 못하면 제한을 유지하고 앱의 상태 확인 화면으로 유도해야 한다.
- **FR-013**: Live Activity는 제한 해제까지 남은 거리와 시간만 표시하고 코인 사용 행동을 제공하지 않아야 한다. 코인 해제는 Shield 화면과 앱 내 활성 제한 화면에서만 시작·확정할 수 있어야 한다.
- **FR-014**: 동일한 규칙 구간의 중복 해제 요청은 코인을 최대 1개만 소모해야 한다.
- **FR-015**: 제한 해제가 완료되지 않으면 코인을 소모한 상태로 남기지 않아야 한다. Shield 요청이 실패·중단·5초 timeout으로 끝났거나 장부 결과가 불명확하면 요청 식별자를 기준으로 상태를 재확인하고, 제한이 해제되지 않은 차감은 원상 복구해야 한다.
- **FR-016**: 해제 예외는 규칙 ID와 해당 반복 구간을 식별하고 재실행·재부팅 후에도 구간 종료 전까지 유지돼야 한다.
- **FR-017**: 해제된 구간이 끝나면 예외도 종료하고 다음 구간은 정상 판정해야 한다.
- **FR-018**: 초기 출시에서는 코인 1개·3개·5개 묶음을 판매하고 StoreKit이 제공하는 각 상품의 현지 가격을 표시해야 한다.
- **FR-019**: 유효하게 확정된 구매만 한 번 코인으로 지급해야 한다.
- **FR-020**: 실패·취소·대기 구매는 확정 전에 코인을 지급하지 않아야 한다.
- **FR-021**: 사용자는 구매·지급·사용·원상 복구·환불 보정의 수량, 상태, 시각을 내역에서 확인할 수 있어야 한다.
- **FR-022**: 앱이 StoreKit에서 검증된 환불·철회 상태를 확인하면 해당 구매의 미사용 코인을 보정하되 잔액을 0 미만으로 만들지 않아야 한다. 서버 없는 초기 범위에서는 앱이 실행되지 않는 동안의 실시간 반영을 보장하지 않아야 한다.
- **FR-023**: 코인의 현금 환전·사용자 간 양도·선물을 제공하지 않아야 한다.
- **FR-024**: 시스템은 로컬 코인 데이터가 없는 재설치·교체 기기에서 동일 iCloud 계정의 기존 CloudKit 장부가 `current`임을 확인한 경우에만, 유효하게 검증된 StoreKit 거래와 연결된 구매 지급에서 코인 사용·보정 내역을 반영해 미사용 구매 코인 잔액과 관련 내역을 복구해야 한다. 이는 소모성 상품의 새 구매나 StoreKit 구매 복원이 아니라 앱이 관리하는 iCloud 잔액 동기화다. 초기 fetch가 완료됐고 원격 장부와 삭제 증거가 모두 없는 최초 활성화는 `setupRequired`로 분류해 **FR-027**의 initial ledger 절차를 적용하고, 일시적 오류나 `current` 미확인 상태는 자동 생성·복구 없이 잠근 채 재시도하며, 삭제가 확인된 경우에만 **FR-040**의 새 장부 절차를 적용해야 한다.
- **FR-025**: Live Activity, 코인, 구매, 해제 문구는 한국어·영어에서 동일한 의미와 가격·잔액 정확성을 유지해야 한다.
- **FR-026**: 제한 대상 앱 식별 정보와 정밀 위치를 결제 목적으로 외부에 제공하지 않아야 한다.
- **FR-027**: 시스템은 `Asia/Seoul` 기준 새달의 첫 앱 실행 또는 Shield 해제 요청에서 같은 iCloud 계정의 해당 월 무료 해제권을 최대 2회 생성해야 한다. 매월 1일 00:00의 background 실행을 보장하지 않는다. 원격 장부와 삭제 증거가 모두 없는 `setupRequired` 최초 사용자가 데이터 한계 고지와 최초 활성화 action을 확정하면 `CoinLedgerSetupService`가 initial ledger와 해당 월 2회를 한 번의 원자적 명령으로 제공해야 한다. Shield가 새달의 첫 요청이면 해당 월 생성과 1회 사용 예약을 하나의 원자적 장부 명령으로 처리해야 한다.
- **FR-028**: 월간 무료 해제권의 미사용 수량은 다음 달로 이월하거나 누적하지 않고, 새 달의 사용 가능 수량을 2회로 갱신해야 한다.
- **FR-029**: 무료 해제권과 구매 코인은 별도 잔액과 변동 내역으로 관리하고 사용자에게 구분해 표시해야 한다.
- **FR-030**: 규칙 해제 시 최신 장부의 현재 서울 기준 월 무료분을 먼저 확인·생성하고 1회 이상 남아 있으면 무료분을 먼저 사용하며, 무료분이 없을 때만 구매 코인 1개를 사용해야 한다. Shield에서 새달 첫 요청이 발생하면 월간 지급 확인과 무료분 예약을 같은 장부 명령에서 원자적으로 처리해야 한다.
- **FR-031**: 월간 무료 지급은 같은 iCloud 계정과 달에 대해 한 번만 처리하고, 여러 기기의 동시 요청·재실행·기기 날짜 변경으로 사용 가능 무료분이 2회를 초과하지 않아야 한다.
- **FR-032**: 구매 코인은 무료 해제권의 월간 갱신과 무관하게 유지하며 만료되지 않아야 한다.
- **FR-033**: iCloud 계정 상태를 신뢰할 수 없어 월간 지급의 중복 여부를 확인할 수 없으면 무료 해제권을 임의로 추가하지 않고, 상태 확인 후 지급을 재시도해야 한다.
- **FR-034**: 월간 무료 해제권의 연월은 `Asia/Seoul` 시간대의 매월 1일 00:00을 경계로 계산하고, CloudKit 서버 시각과 일치하지 않는 미래·과거 월 지급 요청을 확정하지 않아야 한다.
- **FR-035**: 시스템은 지속적인 background location update를 새로 사용하지 않고, 기존 위치 이벤트 또는 앱 실행 시 얻은 신뢰 가능한 위치로만 남은 거리를 갱신해야 한다. 메인 앱이 위치를 전달받으면 ActivityKit을 조정하고, extension만 전달받으면 위치 근거를 저장한 뒤 다음 앱 foreground에서 반영해야 한다. `LocationEvidenceEvaluator`가 `.inside`로 확정한 위치라도 확인 시점부터 5분을 초과하면 거리를 확인 불가로 전환해야 한다.
- **FR-036**: 초기 범위는 앱 서버, ActivityKit push-to-start, App Store Server Notifications를 사용하지 않아야 한다. StoreKit에서 검증된 거래와 같은 iCloud 계정의 CloudKit private database 장부를 사용하되, private zone 삭제·계정 변경·앱 장기 미실행 시 복구와 환불 반영의 한계를 구매 전에 안내해야 한다.
- **FR-037**: 코인 장부의 `current`는 (1) iCloud 계정 사용 가능, (2) 현재 프로세스에서 private database 초기 fetch 완료, (3) 주입 가능한 monotonic clock으로 측정한 마지막 성공 fetch 이후 경과 시간이 5분 이내, (4) 로컬 mirror·`LedgerEpoch`·`CoinAccount`의 epoch 일치, (5) fetch된 `PurchaseGrant`·사용·보정 event projection 완료, (6) 결과 불명 해제 명령이나 pending reconciliation 없음의 조건을 모두 만족한 상태여야 한다. 앱·extension 프로세스가 새로 시작되면 새 fetch가 끝나기 전까지 `current`로 복원하지 않아야 한다. 구매와 해제 직전에는 서버 record를 다시 확인해야 하며, monotonic 경과 시간이 5분을 넘기거나 어느 조건이라도 깨지면 `stale` 또는 해당 실패 상태로 전환해야 한다. wall-clock `syncedAt`은 사용자 표시·진단에만 사용하고 freshness 권한 판정에는 사용하지 않아야 한다. `current`를 확인할 수 없으면 코인 구매 버튼을 비활성화하고 구매 요청을 시작하지 않으며 iCloud 연결·동기화 후 다시 시도하도록 안내해야 한다.
- **FR-038**: 사용자가 Live Activity를 제거한 뒤에도 활성 제한이 남아 있으면 다음 앱 foreground 진입에서 현재 대표 규칙의 Live Activity를 다시 생성해야 한다.
- **FR-039**: 시스템은 코인 기능 최초 활성화와 각 구매 확정 전에 CloudKit 개인 장부를 삭제하면 기존 구매 잔액·사용 내역과 현재 월 무료 해제권을 안전하게 복원하지 못할 수 있음을 명확히 안내해야 한다.
- **FR-040**: `userDeletedZone` 또는 같은 iCloud 계정에서 기존 장부를 보유했다는 지속 증거 뒤 zone 부재로 CloudKit 개인 장부 삭제가 확인되면 코인 구매·사용을 잠그고 로컬 mirror로 자동 복원하거나 자동 초기화하지 않아야 한다. 사용자가 새 장부 시작을 명시적으로 확정한 경우에만 구매 코인 0개·삭제가 확인된 현재 월 무료 해제권 0회로 초기화하고 다음 `Asia/Seoul` 월 경계부터 월간 무료 해제권 지급을 재개해야 한다. 서버 없는 구조에서 사용자가 원격 장부와 삭제 증거를 모두 제거한 새 설치는 최초 사용자와 완전히 구분할 수 없으며, 이 경우 재활성화로 무료분이 다시 생길 수 있다는 한계를 최초 활성화·구매 전 고지해야 한다.
- **FR-041**: Shield의 해제권 사용 요청이 최신 장부의 잔액 부족으로 거부되면 앱의 코인 구매 화면으로 유도하고, iCloud·장부 불가·삭제·재조정 상태이면 앱의 해당 복구 화면으로 유도해야 한다. iOS 26.5 이상에서는 `ShieldActionResponse.openParentalControlsApp`을 사용하며, iOS 26.0~26.4에서는 공식 직접 열기 API가 없음을 안내하고 차단 앱을 닫는 fallback을 사용해야 한다. 앱 이동 요청은 생성 후 5분 이내이고 연결된 제한 구간이 활성일 때 한 번만 소비하며, 만료·중복·종료된 구간의 요청은 삭제해야 한다.

### 핵심 엔티티

- **활성 제한 현황**: 규칙, 적용 구간, 장소·반경, 종료 시각, 최신 거리와 표시 상태.
- **규칙 적용 구간**: 반복 규칙의 특정 날짜에 해당하는 한 번의 시작부터 종료까지를 나타낸다.
- **해제 예외**: 해제한 규칙 ID·적용 구간·만료 시각·코인 변동을 연결한다.
- **코인 잔액/변동**: 현재 사용 가능 수량과 구매 지급·사용·원상 복구·환불 보정 내역을 나타낸다.
- **월간 무료 해제권**: iCloud 계정 기준 연월, 월간 제공 수량, 사용 수량, 마지막 지급 상태를 나타내며 구매 코인과 분리된다.
- **코인 상품/구매 결과**: 코인 수량·현지 가격·판매 상태와 구매의 고유 식별자·처리 상태·잔액 반영 여부를 나타낸다.
- **앱 이동 요청**: Shield 행동 뒤 이동할 코인 구매·iCloud 복구 목적, 생성 시각, 연결된 제한 구간과
  소비 여부를 나타내며 5분 이내에 한 번만 사용할 수 있다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: Live Activity 지원 기기, 권한 허용, 유효한 활성 제한, 앱 foreground 조건을 모두 만족하는 100회 실행 중 95회 이상에서 활성 제한 확인 후 30초 이내에 Live Activity를 확인할 수 있다. 권한 거부·미지원 상태는 모집단에서 제외하고 별도 안전 실패 테스트로 검증한다.
- **SC-002**: 메인 앱이 신뢰할 수 있는 위치를 전달받아 ActivityKit을 조정할 수 있게 된 뒤 30초 이내에 표시 가능한 모든 사례의 남은 거리가 갱신된다. extension만 위치를 전달받은 사례는 다음 앱 foreground 진입 후 30초 이내에 같은 상태를 반영한다.
- **SC-003**: 주입된 시계로 종료 전·종료 경계·종료 후를 검증할 때 표시된 남은 시간과 실제 종료 시각의 차이는 60초를 초과하지 않고, 종료 이후 표시값은 항상 0으로 clamp된다.
- **SC-004**: 앱 내 해제 또는 실기기에서 지원이 확인된 Shield Action 직접 조정은 제한 해제 확인 후 30초 이내에 다른 활성 규칙이 남으면 Live Activity를 다음 대표 규칙으로 갱신하고, 활성 규칙이 없으면 종료한다. Shield Action 직접 조정이 지원되지 않거나 실패·timeout이면 해제·차감의 성공을 유지하고, 앱이 foreground로 진입한 뒤 30초 이내에 같은 최종 상태로 재조정한다.
- **SC-005**: Shield와 앱의 모든 자동 UI 검증 사례에서 해제 대상, 무료 우선·구매 코인 fallback을 포함한 소모 수량, 해제 유효 기간, 겹친 규칙으로 남을 제한을 확정 전에 표시하고, 명시적 확인 행동 없이는 코인을 사용하지 않는다.
- **SC-006**: 동일 규칙 구간에 100회의 중복·동시 해제 요청을 발생시켜도 코인은 최대 1개만 소모된다.
- **SC-007**: 해제 실패·중단 시나리오 100%에서 사용할 수 없는 코인 차감이 남지 않는다.
- **SC-008**: 확정된 구매 100건을 중복 결과·재실행·대기 후 승인으로 재처리해도 각 구매의 코인이 한 번만 지급된다.
- **SC-009**: 실패·취소·대기 구매 100%에서 확정 전 코인이 지급되지 않는다.
- **SC-010**: 한국어·영어 표시 검증에서 실시간 현황, 가격, 잔액, 해제 결과의 핵심 정보 누락·잘못된 언어 표시가 0건이다.
- **SC-011**: 월 변경·신규 가입·재실행·여러 기기 동시 요청을 각 100회 검증해도 계정별 월간 무료 해제권은 정확히 2회를 초과하지 않는다.
- **SC-012**: 월간 갱신 검증 100%에서 남은 무료분은 다음 달로 이월되지 않고 구매 코인 잔액은 변하지 않는다.

## 가정

- 코인 1개는 선택한 활성 규칙 1개의 현재 적용 구간을 종료 시각까지 해제하는 소모성 재화이다.
- 여러 규칙이 같은 앱을 제한하면 코인을 사용한 규칙 외의 제한은 유지된다.
- 코인은 초기 출시에서 1개·3개·5개 소모성 묶음으로 판매하고 가격은 App Store Connect에서 관리한다.
- 매월 무료 해제권은 2회로 갱신하며, 추가 무료 코인, 일일 지급, 광고 보상, 구독, 선물·양도·환전은 초기 범위에 포함하지 않는다.
- 월간 무료 해제권은 달이 바뀌는 순간의 background 실행이 아니라 새달의 첫 앱 실행 또는 Shield 해제 요청에서 지연 생성한다.
- 구매 직후 제한을 자동 해제하지 않고 사용자의 명시적 확인을 받는다.
- 코인 잔액의 복구 주체는 App Store 구매 계정과 다를 수 있는 iCloud 계정이며, 구매 전에 동일 iCloud 계정 유지 필요성을 안내한다.
- 소모성 코인 복구 UI는 StoreKit의 `구매 복원`이 아니라 앱이 관리하는 `iCloud 잔액 동기화` 또는 `iCloud 잔액 복구`로 안내한다.
- 남은 거리는 직선 최소 거리이며 도로·보행 경로나 예상 이동 시간이 아니다.
- 성공 기준은 시스템이 신뢰할 수 있는 상태 변경을 확인한 시점부터 측정한다.
- 이동 중 거리 표시의 갱신 빈도는 기존 위치 이벤트 전달 기회에 따르며 지속 추적을 약속하지 않는다.
- 월간 무료 해제권의 정책 시간대는 `Asia/Seoul`로 고정한다.
- 초기 범위는 별도 앱 서버 없이 StoreKit 2와 CloudKit private database로 운영한다.
- Shield의 앱 직접 열기는 iOS 26.5 이상에서만 공식 지원하며 iOS 26.0~26.4에서는 사용자가 GetUp을 직접 열도록 안내한다.
- 첫 사용자의 90%가 해제 정보를 이해하고 30초 안에 완료하는지는 후속 사용성 검증 목표이며,
  자동화된 구현 완료 게이트에는 포함하지 않는다.

## 의존성 및 범위

- `001-location-app-restriction`의 다중 규칙 평가, 위치 판정, 제한 합집합, 자동 해제가 선행 의존성이다.
- 현재 월 계산, 월간 무료분의 중복 없는 생성과 무료 우선 원자적 예약은 Shield·앱의 코인 해제보다
  먼저 제공해야 하는 공통 선행 능력이다. 월간 잔액 표시·지역화·월 경계 인수 검증은 월간 무료
  해제권 사용자 스토리 범위로 유지한다.
- 제출 시점의 인앱결제, 환불·철회, 소비자 보호 정책을 준수해야 한다.
- 초기 범위는 개인 사용자의 단일 잔액과 자신의 규칙 해제만 다룬다.
