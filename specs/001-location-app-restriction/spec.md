# Feature Specification: 시간·위치 기반 앱 사용 제한

**Feature Branch**: 생성되지 않음

**Created**: 2026-08-20

**Status**: Draft

**Input**: User description: "설정한 시간대와 기준 위치 반경 조건이 모두 충족될 때 선택한 앱의 사용을 제한하고, 조건 해제 또는 권한·위치 오류를 안전하게 처리하는 iOS 앱"

## Clarifications

### Session 2026-08-20

- Q: GetUp 앱이 열려 있지 않거나 기기가 재시작된 뒤에도 조건 충족 시 제한이 자동으로 동작해야 하나요? → A: 앱이 열려 있지 않거나 기기가 재시작된 뒤에도 자동 제한을 계속 지원한다.
- Q: 제한이 활성화된 동안 사용자가 GetUp 기능을 끄거나 규칙을 삭제·변경하려 할 때 어떻게 처리해야 하나요? → A: GetUp 내부에서는 조건이 끝날 때까지 변경과 해제를 막되, 개인 사용자의 시스템 권한 해제나 앱 삭제까지 차단하지는 않는다.
- Q: 위치 정확도가 낮아 사용자가 설정 반경 안인지 밖인지 확실히 구분할 수 없을 때 제한 상태를 어떻게 처리해야 하나요? → A: 위치 확인 불가로 처리하고, 정확한 위치가 확보될 때까지 제한 상태를 변경하지 않는다.
- Q: 각 제한 규칙은 어떤 날짜에 반복 적용되어야 하나요? → A: 사용자가 적용할 요일을 직접 선택한다.
- Q: 사용자 지정 시간대의 최소 길이는 얼마인가요? → A: 자동 제한을 지원하기 위해 최소 15분으로 제한한다.
- Q: 위치·시간 반응 시간과 재부팅 후 자동 복구의 측정 기준은 무엇인가요? → A: 신뢰 가능한 조건 변경이 확인된 뒤 30초 이내 반영하고, 재부팅 후 첫 잠금 해제부터 자동 복구한다.
- Q: 사용자는 기준 위치를 어떻게 선택하나요? → A: 지도에서 핀을 이동해 지정하고 현재 위치 바로가기를 사용하며, MVP에서는 장소·주소 검색을 제공하지 않는다.

### Session 2026-08-21

- Q: 홈의 “새 규칙” 버튼은 여러 규칙을 동시에 저장하는 기능인가요? → A: MVP부터 여러 독립 규칙을 추가·수정한다.
- Q: 여러 규칙의 시간과 위치 조건이 동시에 충족되면 어떤 앱을 제한해야 하나요? → A: 조건을 충족한 모든 규칙의 제한 앱을 합치고, 한 규칙이 끝나면 다른 활성 규칙이 요구하지 않는 앱만 해제한다.

### Session 2026-08-23

- Q: 위치 반경은 어떤 값으로 설정하나요? → A: slider에서 500m, 1km, 2km, 3km, 4km, 5km 중 하나를 선택한다.
- Q: 기준 위치는 규칙마다 새로 입력하나요? → A: 사용자가 장소 이름과 좌표를 저장하고 다른 규칙에서 재사용한다.
- Q: 시간 프리셋을 제공하나요? → A: 프리셋 없이 시작 시각과 종료 시각을 직접 설정한다.
- Q: 15분 미만 시간대는 어떻게 처리하나요? → A: DatePicker에서 15분 미만 구간을 만드는 값을 선택할 수 없게 한다.
- Q: 규칙을 구분하는 이름을 제공하나요? → A: 선택적인 규칙 이름을 제공하며 장소 이름과 별도로 저장한다.
- Q: DST 전환일에 시작·종료 현지 시각이 없거나 두 번 발생하면 어떻게 하나요? → A: 존재하지 않는
  경계는 다음 유효 시각으로 이동하고, 반복되는 시작은 첫 번째 발생, 종료는 두 번째 발생을 사용한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 제한 조건 설정 (Priority: P1)

사용자는 생활 패턴에 맞게 기능이 동작할 시간대, 기준 위치, 위치 반경, 제한할 앱을
설정하여 자신만의 사용 제한 규칙을 준비한다.

**Why this priority**: 제한 조건이 없으면 자동 제한 기능이 동작할 수 없으며, 사용자가 원하는
생활 패턴을 정확히 반영하는 것이 전체 기능의 출발점이다.

**Independent Test**: 사용자가 직접 입력 시간대, 저장하거나 재사용한 기준 위치, 여섯 가지 반경 중
하나, 하나 이상의 앱을 선택하고 저장한 뒤 같은 설정을 다시 확인할 수 있는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 새 제한 규칙을 설정 중일 때, **When** 시작 시간을 06:00, 종료 시간을
   09:00으로 직접 지정하면, **Then** 해당 시간대가 규칙에 반영된다.
2. **Given** 사용자가 시작 시간을 지정했을 때, **When** 종료 시각 DatePicker를 열면,
   **Then** 총 시간 간격이 15분 미만이 되는 종료 시각은 선택할 수 없다.
3. **Given** 사용자가 시간을 설정할 때, **When** 시작 시간을 23:00, 종료 시간을
   06:00으로 지정하면, **Then** 자정을 넘어 다음 날까지 이어지는 시간대로 저장된다.
4. **Given** 사용자가 장소 이름과 지도 핀 좌표를 저장했을 때, **When** 다른 규칙에서 기준 위치를
   선택하면, **Then** 저장된 장소를 다시 선택해 같은 좌표를 사용할 수 있다.
5. **Given** 사용자가 기준 위치와 앱을 선택했을 때, **When** 반경으로 500m, 1km, 2km, 3km,
   4km 또는 5km 중 하나를 선택하고
   설정을 저장하면, **Then** 선택한 시간대·위치·반경·앱이 하나의 제한 규칙으로 보존된다.
6. **Given** 사용자가 기준 위치를 설정 중일 때, **When** 지도에서 핀을 이동하거나 현재 위치
   바로가기를 사용하면, **Then** 해당 좌표가 기준 위치로 선택되고 지도에 표시된다.
7. **Given** 제한 규칙이 이미 저장되어 있을 때, **When** 사용자가 새 규칙 버튼을 선택하면,
   **Then** 기존 규칙을 교체하지 않고 별도의 제한 규칙을 추가할 수 있다.
8. **Given** 사용자가 제한 규칙을 설정 중일 때, **When** 하나 이상의 적용 요일을 선택하고
   저장하면, **Then** 규칙은 선택한 요일에만 반복 적용된다.
9. **Given** 월요일을 적용 요일로 선택하고 23:00부터 06:00까지 설정했을 때,
   **When** 월요일 23:00부터 화요일 06:00 사이가 되면, **Then** 해당 구간은 월요일에 시작한
   하나의 제한 시간대로 평가된다.
10. **Given** 하나 이상의 규칙이 저장되어 있을 때, **When** 사용자가 홈 화면을 열면,
    **Then** 저장된 모든 규칙을 card pager에서 확인할 수 있고 각 규칙의 다음 적용일·요일·시간·
    기준 위치·반경·제한 앱을 확인할 수 있다.
11. **Given** 홈 화면에 예정 규칙이 표시되어 있을 때, **When** 사용자가 수정 메뉴를 선택하면,
    **Then** 해당 규칙의 현재 값을 유지한 편집 화면으로 이동한다.
12. **Given** 사용자가 앱을 처음 실행했을 때, **When** onboarding을 진행하면, **Then** 침대 또는
    문을 활용한 시각적 설명으로 취침과 외출 상황에서 휴대폰 사용을 멈추는 제품 목적을 이해하고
    첫 규칙 설정 또는 홈 화면으로 이동할 수 있다.
13. **Given** 사용자가 시작 또는 종료 시각을 편집할 때, **When** 시간 선택 화면을 열면,
    **Then** 시·분·AM/PM을 각각 위아래로 조정할 수 있고 분은 1분 단위로 선택할 수 있다.
14. **Given** 홈에 여러 예정 규칙이 있을 때, **When** 사용자가 규칙 카드를 좌우로 swipe하면,
    **Then** 시간·위치·반경·제한 앱·수정 행동이 하나의 카드에 묶인 다음 또는 이전 규칙이 표시된다.

### User Story 2 - 조건 충족 시 선택 앱 제한 (Priority: P1)

사용자는 설정 시간대에 설정 위치 반경 안에 머무는 동안 미리 선택한 앱을 열 수 없고,
현재 사용 제한이 활성화되어 있음을 분명히 알 수 있다.

**Why this priority**: 시간과 장소에 따라 산만한 앱 사용을 차단하는 것이 제품의 핵심 가치다.

**Independent Test**: 유효한 설정과 필요한 권한이 준비된 상태에서 시간 및 위치 조건을 모두
충족시킨 뒤, 선택한 앱만 제한되고 제한 화면이 표시되는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 현재 시각이 설정 시간대 안이고 확인된 현재 위치가 설정 반경 안일 때,
   **When** 두 조건이 모두 충족되면, **Then** 사용자가 선택한 앱의 사용 제한이 활성화된다.
2. **Given** 선택한 앱의 제한이 활성화되어 있을 때, **When** 사용자가 해당 앱을 열려고 하면,
   **Then** 현재 사용 제한이 활성화되어 있음을 알리는 제한 화면이 표시된다.
3. **Given** 제한 조건이 충족되어 있을 때, **When** 사용자가 제한 대상으로 선택하지 않은 앱을
   열면, **Then** 이 기능은 해당 앱의 사용을 제한하지 않는다.
4. **Given** 현재 시각이 설정 시간대 밖이거나 현재 위치가 설정 반경 밖일 때,
   **When** 다른 하나의 조건만 충족되면, **Then** 새로운 앱 사용 제한이 활성화되지 않는다.
5. **Given** 유효한 제한 규칙과 필요한 권한이 준비되어 있을 때, **When** GetUp 앱이 열려 있지
   않거나 기기가 재시작된 뒤 시간 및 위치 조건이 모두 충족되면, **Then** 사용자가 GetUp 앱을
   직접 열지 않아도 선택한 앱의 사용 제한이 자동으로 활성화된다.

### User Story 3 - 조건 종료 시 자동 해제 (Priority: P2)

사용자는 설정 위치를 벗어나거나 설정 시간대가 끝나면 별도 조작 없이 선택한 앱을 다시
사용할 수 있다.

**Why this priority**: 필요한 상황이 끝난 뒤에도 제한이 남으면 정상적인 앱 사용을 방해하므로
신뢰할 수 있는 자동 해제가 필요하다.

**Independent Test**: 활성 제한 상태에서 위치 범위를 벗어나는 경우와 시간대가 끝나는 경우를
각각 만들고, 두 경우 모두 제한이 해제되는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 앱 사용 제한이 활성화되어 있을 때, **When** 확인된 현재 위치가 설정 반경 밖으로
   변경되면, **Then** 선택한 앱의 사용 제한이 자동으로 해제된다.
2. **Given** 앱 사용 제한이 활성화되어 있을 때, **When** 설정된 종료 시각에 도달하면,
   **Then** 현재 위치와 관계없이 선택한 앱의 사용 제한이 자동으로 해제된다.
3. **Given** 자정을 넘는 23:00부터 06:00까지의 시간대가 설정되어 있을 때,
   **When** 다음 날 06:00에 도달하면, **Then** 활성 제한이 자동으로 해제된다.
4. **Given** 앱 사용 제한이 활성화되어 있을 때, **When** 사용자가 GetUp 내부에서 기능을 끄거나
   규칙을 변경 또는 삭제하려 하면, **Then** 요청은 거부되고 제한 종료 조건이 안내된다.

### User Story 4 - 권한 및 위치 문제 안내 (Priority: P2)

사용자는 기능에 필요한 권한이 없거나 현재 위치를 확인할 수 없을 때 그 사실과 해결 방법을
확인하여, 제한 기능이 동작하지 않는 이유를 이해할 수 있다.

**Why this priority**: 권한과 위치 상태가 불명확하면 사용자는 제한 상태를 예측하거나 문제를
해결할 수 없으며, 잘못된 위치 판정은 의도하지 않은 제한을 만들 수 있다.

**Independent Test**: 필요한 각 권한을 거부한 상태와 위치를 확인할 수 없는 상태를 각각 만들고,
정확한 안내와 안전한 제한 상태 유지가 이루어지는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 사용 제한에 필요한 권한 중 하나 이상이 승인되지 않았을 때, **When** 사용자가
   제한 기능을 설정하거나 상태를 확인하면, **Then** 필요한 권한과 승인 방법이 안내된다.
2. **Given** 제한이 비활성 상태이고 현재 위치를 확인할 수 없을 때, **When** 설정 시간대가
   시작되면, **Then** 위치 확인 불가 상태를 알리고 새로운 제한을 활성화하지 않는다.
3. **Given** 제한이 활성 상태이고 현재 위치를 일시적으로 확인할 수 없을 때, **When** 위치 확인이
   실패하면, **Then** 사용자에게 상태를 알리고 위치 실패만을 근거로 제한 상태를 변경하지 않는다.
4. **Given** 위치를 확인할 수 없는 동안 제한이 활성 상태일 때, **When** 설정 종료 시각에
   도달하면, **Then** 시간 조건에 따라 제한을 해제한다.
5. **Given** 현재 위치의 오차 범위가 설정 반경 경계와 겹칠 때, **When** 시스템이 반경 안팎을
   확정할 수 없으면, **Then** 위치 확인 불가 상태를 알리고 위치를 근거로 제한 상태를 변경하지
   않는다.

### Edge Cases

- 시작 시각과 종료 시각이 같은 값은 24시간 제한으로 해석하지 않고 DatePicker의 유효한 종료
  시각으로 제공하지 않는다.
- 시작 시각과 종료 시각 사이가 15분보다 짧아지는 값은 DatePicker에서 선택할 수 없게 한다.
- 현재 위치와 위치 오차 범위가 모두 설정 반경 안에 있고 위치가 경계와 정확히 일치하면 반경
  안으로 판단한다. 위치 오차 범위가 경계와 겹치면 위치 확인 불가로 처리한다.
- 위치가 반경 경계 주변에서 반복적으로 안팎으로 바뀔 때도 가장 최근의 신뢰 가능한 위치
  판정을 사용하며, 같은 판정에 대한 제한 적용이나 해제를 중복 수행하지 않는다.
- 제한이 활성화된 동안에는 GetUp 내부에서 시간대, 기준 위치, 반경, 선택 앱을 변경하거나 기능을
  끄고 규칙을 삭제할 수 없으며, 시간 종료 또는 확인된 위치 이탈 후 변경할 수 있다.
- 여러 규칙의 시간·위치 조건이 동시에 충족되면 활성 규칙의 제한 앱 합집합을 적용한다. 일부
  규칙이 종료되면 남은 활성 규칙이 요구하는 앱은 계속 제한하고 더 이상 필요하지 않은 앱만
  해제한다.
- 개인 사용자가 시스템 설정에서 필수 권한을 해제하거나 GetUp을 삭제하는 플랫폼 수준의 우회는
  앱 내부에서 차단할 수 있는 범위에 포함하지 않는다.
- 기기 현지 시각 또는 시간대가 변경되면 변경된 현지 시각을 기준으로 조건을 다시 평가하되,
  동일한 상태 변경을 중복 적용하지 않는다.
- DST 전환으로 시작 또는 종료 현지 시각이 존재하지 않으면 해당 경계를 다음 유효 현지 시각으로
  이동한다. 같은 현지 시각이 두 번 발생하면 시작 경계는 첫 번째 발생, 종료 경계는 두 번째 발생을
  사용하며 시작은 포함하고 종료는 포함하지 않는다.
- 자정을 넘는 시간대의 적용 요일은 시작 시각이 속한 요일이며, 다음 날 종료 시각까지 같은
  시간대가 이어진다.
- 선택한 앱이 제거되거나 더 이상 제한 대상이 될 수 없으면 해당 앱을 제외하고 사용자에게
  설정 점검이 필요함을 알린다.
- 기준 위치가 없거나 제한할 앱이 하나도 선택되지 않으면 제한 기능을 활성화할 수 없다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 프리셋 없이 시작 시각과 종료 시각을 직접 설정할 수 있어야 한다.
- **FR-002**: 시스템은 총 시간 간격이 15분 미만이 되거나 시작·종료 시각이 같은 값을 DatePicker의
  선택 가능한 종료 시각으로 제공해서는 안 된다.
- **FR-003**: 시스템은 직접 설정한 시작·종료 시각을 기기 현지 시각 기준의 반복 시간대로
  저장해야 한다.
- **FR-004**: 시스템은 종료 시각이 시작 시각보다 이른 경우 시간대를 자정을 넘어 다음 날까지
  이어지는 구간으로 해석해야 한다.
- **FR-005**: 시스템은 시작 시각과 종료 시각이 같은 직접 설정의 저장을 막고 유효한 시간 입력을
  안내해야 한다.
- **FR-006**: 사용자는 지도에서 핀을 이동하거나 현재 위치 바로가기를 사용해 제한 조건의 기준
  위치를 설정할 수 있어야 한다.
- **FR-007**: 사용자는 slider에서 기준 위치 반경으로 500m, 1km, 2km, 3km, 4km 또는 5km 중
  하나를 선택할 수 있어야 하며 중간 임의 값은 저장할 수 없어야 한다.
- **FR-008**: 사용자는 사용을 제한할 앱을 하나 이상 선택할 수 있어야 한다.
- **FR-009**: 시스템은 시간대, 기준 위치, 반경, 제한 앱 선택이 모두 유효한 경우에만 제한
  규칙을 활성화할 수 있어야 한다.
- **FR-010**: 시스템은 설정된 시간 조건과 확인된 위치 조건이 모두 충족될 때만 선택한 앱에
  새로운 사용 제한을 적용해야 한다.
- **FR-011**: 시스템은 현재 위치와 위치 오차 범위가 기준 위치의 선택 반경 안에 있고 현재 위치가
  반경 이내이거나 경계와 일치할 때 위치 조건이 충족된 것으로 판단해야 한다.
- **FR-012**: 시스템은 제한된 앱을 열려고 할 때 현재 사용 제한이 활성화되어 있음을 알리는
  제한 화면을 표시해야 한다.
- **FR-013**: 시스템은 사용자가 선택하지 않은 앱을 이 기능으로 제한해서는 안 된다.
- **FR-014**: 시스템은 신뢰 가능한 위치 판정에서 사용자가 설정 반경을 벗어난 것으로 확인되면
  활성 제한을 자동으로 해제해야 한다.
- **FR-015**: 시스템은 설정 시간대의 종료 시각에 도달하면 현재 위치 상태와 관계없이 활성 제한을
  자동으로 해제해야 한다.
- **FR-016**: 시스템은 필요한 권한이 모두 승인되지 않은 경우 새로운 사용 제한을 적용해서는
  안 된다.
- **FR-017**: 시스템은 승인되지 않은 필수 권한의 종류와 사용자가 해당 권한을 승인할 수 있는
  방법을 안내해야 한다.
- **FR-018**: 시스템은 현재 위치를 확인할 수 없는 경우 그 상태를 사용자에게 알려야 한다.
- **FR-019**: 시스템은 현재 위치를 확인할 수 없는 동안 위치 조건을 추정해서 새로운 제한을
  활성화하거나 기존 제한을 위치만을 근거로 해제해서는 안 된다.
- **FR-020**: 시스템은 위치를 확인할 수 없더라도 시간대 종료가 발생하면 활성 제한을 해제해야
  한다.
- **FR-021**: 시스템은 제한 상태가 이미 목표 상태와 같으면 같은 제한 적용 또는 해제 작업을
  중복 수행하지 않아야 한다.
- **FR-022**: 시스템은 제한이 비활성 상태일 때 사용자가 제한 규칙을 변경해 저장하면 새 규칙으로
  시간 및 위치 조건을 다시 평가하고 제한 상태를 일치시켜야 한다.
- **FR-023**: 시스템은 제한이 활성 상태인 동안 GetUp 내부의 기능 끄기, 제한 규칙 변경 및 삭제를
  허용해서는 안 되며, 해당 작업이 가능해지는 종료 조건을 안내해야 한다.
- **FR-024**: 시스템은 현재 기능 상태를 최소한 비활성, 제한 활성, 권한 필요, 위치 확인 불가로
  구분하여 사용자에게 보여줘야 한다.
- **FR-025**: 사용자는 제한 규칙을 반복 적용할 요일을 하나 이상 선택할 수 있어야 하며,
  시스템은 선택한 요일에만 규칙을 반복 적용해야 한다.
- **FR-026**: 시스템은 GetUp 앱이 열려 있지 않거나 기기 재시작 뒤 첫 잠금 해제가 완료된 후에도
  사용자가 앱을 직접 열 필요 없이 저장된 규칙의 시간 및 위치 조건을 평가하고 제한 상태를
  자동으로 일치시켜야 한다.
- **FR-027**: 시스템은 개인 사용자가 시스템 설정에서 필수 권한을 해제한 사실을 확인하면 권한
  필요 상태를 표시해야 하며, 시스템 권한 해제나 앱 삭제를 GetUp 내부 제한으로 차단할 수 있다고
  사용자에게 안내해서는 안 된다.
- **FR-028**: 시스템은 현재 위치의 오차 범위가 설정 반경 경계와 겹쳐 안팎을 확정할 수 없으면
  위치 확인 불가로 처리해야 한다.
- **FR-029**: 시스템은 MVP부터 여러 독립 제한 규칙을 저장하고 각 규칙을 추가·확인·수정할 수
  있어야 한다.
- **FR-030**: 시스템은 자정을 넘는 시간대에서 시작 시각이 속한 요일을 적용 요일로 판단하고,
  다음 날 종료 시각까지 같은 시간대를 이어서 평가해야 한다.
- **FR-031**: 시스템은 직접 설정한 시간대의 길이가 15분 이상인 경우에만 제한 규칙을 저장하고
  활성화할 수 있어야 한다.
- **FR-032**: 시스템은 MVP에서 기준 위치의 장소·주소 검색 기능을 제공하지 않아야 한다.
- **FR-033**: 앱과 모든 app extension은 iOS 26 이상을 deployment target으로 지원해야 한다.
- **FR-034**: 시스템은 홈 화면의 card pager에 저장된 모든 유효 규칙을 표시해야 한다. 오늘 적용되는
  규칙을 먼저 두고, 나머지는 각 규칙의 다음 적용 시점 순으로 정렬해야 한다.
- **FR-035**: 홈의 각 규칙은 자신의 다음 적용일, 적용 요일, 시간대, 기준 위치, 반경 및 제한 앱을
  사용자가 확인할 수 있는 형태로 제공하고 해당 규칙 편집으로 연결해야 한다.
- **FR-036**: 홈 화면은 기존 규칙을 교체하지 않고 별도의 새 제한 규칙을 추가하는 진입점을
  제공해야 한다.
- **FR-037**: onboarding은 침대 또는 문을 중심 소재로 사용해 취침과 외출 상황에서 휴대폰 사용을
  멈추게 하는 앱의 목적을 텍스트에만 의존하지 않고 전달해야 한다.
- **FR-038**: 여러 규칙의 시간 및 위치 조건이 동시에 충족되면 시스템은 활성 규칙들이 선택한
  제한 앱의 합집합을 적용해야 하며, 일부 규칙 종료 시 남은 활성 규칙이 요구하지 않는 앱만
  해제해야 한다.
- **FR-039**: 사용자는 장소 이름과 지도 핀 좌표를 하나의 저장 장소로 보존하고 다른 제한 규칙의
  기준 위치로 재사용할 수 있어야 한다.
- **FR-040**: 시스템은 선택적인 규칙 이름과 장소 이름을 서로 다른 값으로 저장하고 표시해야 한다.
- **FR-041**: 홈 화면은 시작·종료 시각을 `06:00 AM` 형식으로 표시하고 AM/PM을 시간 숫자보다
  작은 시각적 계층으로 표현해야 한다.
- **FR-042**: 시작·종료 시각 선택 화면은 시·분·AM/PM을 각각 독립적인 세로 wheel로 제공하고,
  분 wheel은 1분 단위로 모든 값을 선택할 수 있어야 한다. 전체 규칙 시간 표기는 12시간제와
  AM/PM을 일관되게 사용해야 한다.
- **FR-043**: 홈의 각 예정 규칙은 시간 영역과 위치·반경·제한 앱·수정 영역을 하나의 swipeable
  card container로 묶어야 한다. 저장된 모든 규칙은 좌우 swipe와 현재 page indicator로 탐색하고,
  카드 내부 정보가 서로 다른 규칙으로 오해되지 않도록 시각적으로 연결해야 한다.
- **FR-044**: 저장된 모든 유효 규칙은 서로 독립적으로 적용되어야 한다. 여러 규칙이 동시에
  시간·위치 조건을 충족하면 `FR-038`에 따라 제한 앱 합집합을 적용해야 하며, 홈에서 보이는 카드
  순서나 현재 선택된 카드가 실제 규칙 적용 여부에 영향을 주어서는 안 된다.
- **FR-045**: 시스템은 DST 전환으로 존재하지 않는 시작·종료 현지 시각을 다음 유효 시각으로
  이동하고, 반복되는 시작 시각은 첫 번째 발생, 반복되는 종료 시각은 두 번째 발생으로 평가해야 한다.

### Key Entities *(include if feature involves data)*

- **제한 규칙**: 고유 식별자, 선택적 규칙 이름, 반복 적용 요일, 시간대, 저장 장소 참조, 반경,
  제한 대상 앱, 기능 활성 여부를 하나로 묶은 독립 사용자 설정이다.
- **시간대**: 시작 시각과 종료 시각으로 구성되며, 같은 날 안의 구간 또는 자정을 넘는 구간을
  나타낸다.
- **저장 장소**: 고유 식별자, 사용자가 지정한 장소 이름과 지도 핀 좌표를 묶어 여러 규칙에서
  재사용하는 위치 설정이다.
- **위치 조건**: 저장 장소와 500m, 1km, 2km, 3km, 4km 또는 5km의 반경으로 구성되며, 확인된 현재 위치와 그 오차
  범위가 조건을 확실히 충족하는지 판단하는 기준이다.
- **제한 대상 앱**: 제한 규칙이 활성화될 때 사용이 차단되어야 하는 사용자의 앱 선택 목록이다.
- **제한 상태**: 현재 제한의 활성 여부와 그 판단 근거인 시간, 위치, 권한 및 위치 확인 상태를
  나타낸다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신규 사용자의 90% 이상이 안내 없이 3분 이내에 시간대, 기준 위치, 반경, 제한 앱을
  포함한 유효한 제한 규칙을 저장할 수 있다.
- **SC-002**: 신뢰 가능한 시간 및 위치 조건 변경이 확인된 시점부터 30초 이내에 95% 이상의
  제한 상태 변경이 실제 선택 앱의 사용 가능 상태에 반영된다.
- **SC-003**: 검증된 시간·위치 조건 조합의 100%에서 두 조건이 모두 충족될 때만 새로운 제한이
  활성화된다.
- **SC-004**: 신뢰 가능한 위치 범위 이탈 또는 시간대 종료가 확인된 검증 사례의 100%에서 확인
  시점부터 30초 이내에 활성 제한이 해제된다.
- **SC-005**: 권한 미승인 또는 위치 확인 불가 검증 사례의 100%에서 원인을 식별할 수 있는 상태
  안내가 표시되고, 잘못된 위치 추정에 기반한 새 제한이 발생하지 않는다.
- **SC-006**: 자정을 넘는 시간대의 시작 전, 활성 중, 종료 후 검증 사례 100%에서 기대한 제한
  상태가 유지된다.
- **SC-007**: 사용성 평가 참여자의 85% 이상이 현재 제한 활성 여부와 권한 또는 위치 문제의 해결
  방법을 첫 시도에 정확히 이해한다.
- **SC-008**: GetUp 앱이 열려 있지 않은 상태와 기기 재시작 뒤 첫 잠금 해제 이후의 검증 사례
  100%에서 사용자가 GetUp 앱을 직접 열지 않아도 신뢰 가능한 조건 변경이 확인되면 저장된
  규칙에 맞는 제한 상태가 적용된다.
- **SC-009**: 활성 제한 중 GetUp 내부의 기능 끄기, 규칙 변경 및 삭제 시도의 100%가 거부되고
  제한 종료 조건이 사용자에게 표시된다.
- **SC-010**: 위치 오차 범위가 설정 반경 경계와 겹치는 검증 사례 100%에서 위치 확인 불가 상태가
  표시되고 위치를 근거로 한 제한 활성화 또는 해제가 발생하지 않는다.
- **SC-011**: 선택한 요일과 선택하지 않은 요일 및 자정을 넘는 시간대를 포함한 검증 사례 100%에서
  시작 요일 기준으로 기대한 제한 상태가 적용된다.

## Assumptions

- 첫 번째 버전의 지원 운영체제는 iOS 26 이상이며, 이전 iOS 버전 호환성은 제공하지 않는다.

- 첫 번째 버전부터 여러 독립 제한 규칙을 지원하며, 각 규칙은 사용자가 선택한 하나 이상의 요일에
  반복 적용된다.
- 시간대 판단은 기기에 설정된 현재 현지 시각을 기준으로 한다.
- 기준 위치와 앱 목록의 선택은 사용자가 명시적으로 완료한다.
- 기준 위치 선택 지도는 핀 이동과 현재 위치 바로가기를 제공하며 장소·주소 검색은 후속 범위다.
- 장소 이름은 사용자가 직접 입력하며 주소 검색이나 reverse geocoding 결과를 의미하지 않는다.
- 사용자는 위치 확인과 선택 앱 제한에 필요한 시스템 권한을 승인할 수 있는 기기를 사용한다.
- 운영체제가 허용하는 앱만 제한 대상으로 선택할 수 있으며, 운영체제 자체의 필수 기능은 이
  기능의 제한 대상이 아니다.
- 이 기능은 사용자의 기기 안에서 동작하며 계정 간 설정 동기화와 원격 관리는 첫 번째 버전의
  범위에 포함하지 않는다.
- 위치 확인 불가는 새로운 위치 판정을 만들지 않으며, 마지막 제한 상태는 시간대 종료나 사용자의
  시스템 권한 해제 같은 외부 상태 변경이 발생할 때까지 위치 실패만으로 변경되지 않는다.
- 개인용 앱 제한 권한은 사용자가 시스템 설정에서 해제하거나 앱 삭제로 우회할 수 있으며,
  GetUp은 활성 제한 중 앱 내부의 변경과 해제만 막는다.
- 물리적 위치 경계 통과와 시스템이 신뢰 가능한 위치 변경을 확인하는 시점 사이에는 기기 상태와
  환경에 따른 지연이 발생할 수 있다.
- 재부팅 후 자동 복구는 사용자가 기기의 첫 잠금 해제를 완료한 시점부터 적용된다.
